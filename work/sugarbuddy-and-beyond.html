SugarBuddy and Beyond

For an NLP course, I turned SugarBuddy's check-in concept into a synthetic benchmark dataset, then generalized the method to nine more conditions.

My role
Everything solo: the taxonomy, data generation, evaluation, and a full citation check on every medical claim.
Course
NLP (097215), Technion
When
2026
Tools
Python, pandas, scikit-learn, CatBoost, LightGBM, TabPFN, LoRA fine-tuning, an LLM for text authoring

The problem

A dataset that pairs free text with structured columns is only an interesting benchmark if both parts actually matter. If a model does well just by reading the table, or just by reading the text, it isn't testing anything about combining them. MulTaBench, a benchmark from my NLP course, gives a concrete test for this: run five tabular learners under four conditions each, and a dataset only counts as genuine text-tabular if a joint model beats both single-modality baselines, and fine-tuning the text encoder on the target beats a frozen one — for at least 3 of the 5 learners.

The assignment was to curate one dataset that passes. I built ten.

What I did

1

Built SugarBuddy as a synthetic dataset

Modeled on my own SugarBuddy app's check-in flow: a 94-cause taxonomy of glucose anomalies grounded in diabetes literature, structured CGM/check-in features that hint at the cause without giving it away, and a free-text note authored at one of four calibrated difficulty tiers.

2

Audited the text with a cheap probe

A TF-IDF + logistic-regression classifier tries to guess the cause from the note alone. It caught a tier that was accidentally too predictable; I rewrote the leaking rows and re-verified it fell back to near-chance accuracy.

3

Generalized it into a reusable template

Taxonomy → noisy structured profile → a cheap pre-text signal check → tiered free-text → the same probe audit. I validated it on nine more pediatric conditions (migraine, lupus, DKA, anaphylaxis, and others), each re-evaluated at 3 folds instead of a single-fold spot check.

4

Checked every medical claim before submitting

The taxonomies cite 145 pieces of medical literature. I verified each one individually against the actual paper — found 13 that were overstated, mis-sourced, or unconfirmable, and fixed every one before submission.

What I found

5 / 5learners passed cleanly for SugarBuddy, the main dataset, well past the 3/5 bar
5 of 10datasets passed the benchmark's full curation criteria
145literature citations checked individually before submission

The failures were as informative as the passes. Two datasets bracketed a U-shaped relationship between a dataset's structured-only signal and whether it passes: one with too strong a structured signal saturated the joint model, leaving fine-tuning nothing to add; one too weak failed the basic combined-signal test outright. A fine-tuning-capacity fix discovered on a failing pilot — reducing how much the text encoder was allowed to adapt — turned out to be exactly what was needed to rescue the one weak learner in SugarBuddy itself, the dataset the whole method was built to pass.

What I'd do next

Right now every row has a definite cause — there's no "unknown" label, even though a real agent sometimes can't attribute one confidently. I skipped it deliberately since it would dilute the curation margins, but it's the honest next step. I'd also like to try the same template on a condition that combines images with text and structured data, which the underlying benchmark supports but none of my ten datasets attempted.
